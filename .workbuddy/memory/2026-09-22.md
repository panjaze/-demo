## 第三十五次迭代：确认当前流派失衡——进攻流是负收益（设计结论）

**用户问**：进攻流是否不如种田流？**确认：是，且比"不如"更严重——进攻流目前是负收益行为**。

**数据支撑的对比**：
- 进攻流成本：主城到敌方主城 ~26 格走廊 × 2⚡ = 52⚡+（绕行更多），到达后还要面对守军（60 兵上限驻军）+ 塔（2~7/秒杀伤）+ 主城血量 60~168；收益 = 唯一胜利条件，但**当前贯通 bug 导致连"到达"都做不到**
- 种田流成本：铺路到资源点 ~10 格 × 2⚡ + 12 兵清守军 ≈ 32⚡；收益 = 资源点 +20/10s **永续**（占领不需驻守）+ 建筑产出滚雪球；风险 = **零**（AI 的进攻走廊同样修不过来，bug 对称生效）
- 双方都种田 = 永远平局 → 这就是"30/60 分钟无胜负"的另一个视角：**不是游戏太慢，而是没有对抗压力逼迫任何一方进攻**

**原因分三层**：
1. Bug 层：走廊贯通停滞（第三十四次迭代待查）——修复后进攻流至少"能走通"
2. 成本结构层：攻城是多阶段消耗（野战/磨建筑/塔/血量），而种田产出永续——修好 bug 后性价比仍需校准
3. **对抗压力层（核心）**：双方都没有被迫进攻的理由。真正的平衡杠杆是给种田流制造风险——AI 第二批的"进攻性深化"（AI 会主动修路打过来）正是为此

**下一步顺序**：① 修贯通 bug → ② AI 进攻性深化（让种田流有威胁）→ ③ 重跑胜负分布验证两流派平衡

## 第四十四次迭代：修放置丢卡 + 遗物领取死循环（用户实测报障）

**两个 bug 都出在上一轮的新交互代码里**：

1. **点击建筑牌无法放置且卡消失**：进入放置模式时把卡从手牌移走（学道路牌），但 `build()` 是**从手牌取卡**的——放置失败时卡既不在手里也没上地图，卡在模式里；再点别的卡覆盖模式 → 卡永久消失。
   **修复**：placeMode 进入时**卡保留在手牌**（build 正常取卡消耗，失败/取消/Esc 都不丢）；startDrag 清 placeMode（拖卡不留陈旧模式）；Esc 直接取消（原"退回手牌"逻辑会**复制**一张卡，一并修掉）。
2. **遗物点击无法领取**：`pickReward` 重写时删掉了 `Game.pickRewardCard`，把它里面"**清除 pendingReward**"的副作用一起删了 → 领取后 modal 关闭，render 发现 pendingReward 仍为 true → **立刻重弹三选一**，表现为"点了没反应、弹窗关不掉"（其实遗物已获得，但弹窗永远在）。
   **修复**：pickReward 显式 `Game.state.pendingReward = false`。

**教训（重要）**：删一个函数时，**它的副作用也要跟着迁移**——这次丢的就是 `pendingReward = false`。"点击后界面刷新了但状态没变"这类症状，优先查触发条件的重入循环。
**模式设计原则**：进入"放置/瞄准模式"时**不要移动资源**（卡留原地），模式只是"下一个点击的意图"；资源在动作成功时才消耗。道路牌是例外（多格铺设需要预扣）。

## 第四十五次迭代：修遗物点击无效的真根因（UI.log 不存在）+ 方法完整性检查固化

**上一轮的修复不完整——真根因**：`UI` 没有 `log` 方法，而 `pickReward` 调用了 `this.log(...)`：
执行顺序 = relics.push ✓ → pendingReward=false ✓ → **this.log 抛 TypeError** → 后面的 rewardChoices 清空/关弹窗/render 全部不执行。
症状完美匹配用户描述：点第一件遗物（静默入账但弹窗留在屏上）→ 再点任何遗物 → "已拥有"守卫早退 → "点击无效"。且这个卡死的 modal 盖住手牌，**连带解释了"点手牌没反应"**。

**修复**：`this.log` → `Game.log` + `UI.hint`。并 grep 确认 ui.js 再无 `this.log(`。

**系统性收尾（把这类 bug 永久堵死）**：
- 写了静态检查：`this.x()` 调用 vs 方法定义比对（ui.js + game.js）——**game.js 还抓到一个死代码**：旧版 `adjCount(cell, wantType)` 调用了不存在的 `this.neighbors`（被新版 gx/gy 签名覆盖成死代码），以及引用已删除 `cost` 字段的 `costOf`——一并清理
- 检查固化进 **idcheck.js**（第四层检查：方法调用完整性），以后每次 `node test/run.js` 自动跑

**校验**：三层全绿 —— 自检 **187** + 冒烟 **19** + id 检查 **19** = **225 项**。

**教训**：① **交互层的 TypeError 不会白屏**——它只杀死当前事件处理器，表现为"点了没反应"，console 里有红色报错但用户不看 console；② 静态方法完整性检查是这类 bug 的廉价疫苗；③ 三层测试都测不到 UI 运行时错误——idcheck 的静态检查是当前唯一的覆盖手段。
