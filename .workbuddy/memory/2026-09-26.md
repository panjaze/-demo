## 美术资源接入的耦合评估（结论：低阻塞、有返工风险）

- **事实**：全项目**零外部图片**——`grep .png/.jpg/drawImage` 只在 `engine.js:282` 有色键抠像 helper（未启用）。
  建筑/资源点是 `sandbox.js` 里 `drawBuildings()` 的闭包 `tile()` 画的：**emoji 字形 + 纯色方块 + 类型名/等级文字 + 防御值血条**。
- **接入点**：`sandbox.js` 的 `tile()` 一处 + `ui.js` 卡面 + 可能的地形绘制 ≈ **2~3 处**；`game.js` 纯逻辑不碰渲染 → 规则改动**不会阻塞**美术，反之亦然。
- **收益>>>成本的做法**：加 `CFG.assets.enabled` 开关（默认 false 走 emoji），接入与新创新 slicer 解耦，漏改也只是降级成 emoji、不会白屏。
- **真正的代价是返工不是阻塞**：一旦锁美术，等于把「6 种建筑 × 3 级 / 俯视斜 45° / tile 60 逻辑 px」这些设计假设一起钉死，改一条就要重画。（所幸这两个数已跨 5 次修订没动。）
- ⚠️ **像素风 C2 有额外技术成本**：tile 60 逻辑 px + UI scale + 相机缩放 → 非整数倍缩放会糊/出摩尔纹，保住颗粒感必须 `imageSmoothingEnabled=false` + 整数倍绘制；绘本/厚涂天然适合缩放。
