## 参考游戏考据

### 《卡牌城镇》= **Cardboard Town**（策划案 §3.1 的第一顺位参考）

Steam 上的卡牌驱动城市建造 roguelite，纸模/折叠美术风格。**用户明确点名要结合它做设计**，故记录其机制：

| 机制 | 内容 |
|---|---|
| 核心循环 | 每回合获得随机卡牌 → 消耗**金币**打出手牌 → 在城市地图上摆放建筑/道路 → 管理四类资源 |
| 手牌 | 初始 4 张；每回合随机从卡组抽 1 张；**卡组抽完洗牌重抽** |
| 卡牌三分类 | ① **道路牌**（铺路，**大多数建筑的门必须连到道路才能建造**——"要致富先铺路"）② **建筑牌**（提供人口或资源点数）③ **功能牌**（打出不建造，只发挥效果：摸牌/换牌/弃牌） |
| 资源 | 水 / 电 / 安全 / 环境（任一项降到 0 以下 → 1 个警报，**3 个警报 Game Over**） |
| 资源联动 | 火电厂发电但污染环境；警察局提高安全但耗电 → 逼玩家在平衡中取舍 |
| 麻烦计时器 | 随回合数增长；到 3 点出小麻烦，到 7 点出**灾难**（长时效 Debuff） |
| 警卫点数 | 唯一用途是消除灾难 |
| 人口 | 达标 → 玩家等级提升 + 城市规模增大 + **随机获得一个被动属性** |
| 地图 | 城镇最中心是**被道路包围的市政府大楼** |
| 美术亮点 | 建筑打出时的**翻转/折叠动画**（标志性爽点） |

**与本项目的异同**：抽卡是建造唯一来源 ✓ / 卡牌驱动城市逐渐成形 ✓ / 功能牌＝我们的效果牌 ✓。差别是它**无商店**（靠回合抽卡）、费用花在**打出**而非买卡，且重心在**地图空间规划**（道路连通），而酒馆战棋重心在**商店构筑**。

**待用户拍板的一条机制建议**：借鉴"建筑必须连路"（方案 A 加道路卡 / 方案 B 改为"新建筑必须与已有建筑相邻" / 不加）。

- **跨城市区建造（用户确认）**：敌方**可以**在其占据的我方城市空地上用**自己的卡与物资**建造；**不要求士兵在场**，只要格子归属本方。上限**按城市区分别计算**（每个城市区各自 10 格 + 每种 3 座）。用户判定"士兵须在城门节点"的约束不必要——那块地离建造方远，原主人回防即可清掉。
- **空地收复**：该格**无敌方建筑**时，我方士兵站上己方城门节点 → 点击即**免费收复**；若已建有敌方建筑，必须先打掉其防御值。
- **城市建筑防御值不自动恢复**（用户确认）。第一版无修复手段，受损建筑永久残血；用户计划后续做"花能量修建筑"的卡。
- **底层性质（重要）**：数量抵消下伤害是**等量交换**——1 个士兵最多换 1 点防御值。所以"磨血"与"一次打掉"**总成本相同**，无折扣可套利，因此不需要防御值自动恢复来抑制骚扰。
- **部队模型（V3.1 大改）**：**只有 1 种普通士兵**，战斗强度 1，**无 HP / ATK / 等级 / 兵种 / 克制 / 技能**；以「个」计数。
- **战斗 = 数量抵消**：同一节点同时有双方士兵即**立即结算一次**（事件驱动）；少的一方全灭，多的保留差值；数量相同则同归于尽。
- **量纲统一为「个」**：兵营每 20/16/12 秒出 **5/6/7 个**；士兵场上上限 **60**；建筑守军 **15/25/40**；资源点守军 **10**；**主城防御值 100**；防御塔每秒消灭 **2/4/7** 个（防御值 25/45/70，**可被士兵摧毁**）。
- **占领**：清空守军后幸存即**瞬时占领**（取消进度条）；等级与产能**完整保留**；下个经济 Tick 生效；**不做补给线**；防反复易手靠"占领后立即恢复满额守军"。
- **经济防滚雪球**：建筑位上限 **10 格** + **每种建筑最多 3 座**（新增规则，替代成本递增）；建造成本固定；外围产出为同级 2 倍；开局自带 3 座外围建筑。
- **邻接加成仅 2 条**：兵营相邻农田（产兵间隔 −20%）、防御塔相邻主城（杀敌数 +50%、主城防御值 +20%）；同建筑最多吃 2 个来源。
- **卡牌（第四次修订 · 酒馆战棋式「开牌 + 差别定价」）**：花 **1 能量**翻开 **5 张候选卡**（保证 ≥3 种不同建筑），每张按**标价**买进手牌 —— 农田 1 / 工坊 2 / 能源站 3 / 兵营 4 / 防御塔 5（能量）。可反复花 1 能量重开、**不限次数**。手牌上限 5，可主动弃牌。**暂不做部队卡**（用户后续版本会做新卡）。
- **第四次修订取消的旧规则**：卡组 10 张与洗牌重抽、抽卡成本 `8 + 次数×2` 递增、全部保底机制、开局赠送 5 张手牌。
- **能量尺度（第七次修订 · 已跑批验证）**：初始能量 **20**；**主城自带能量产出 Lv1~Lv5 = +2/+3/+4/+5/+6 每 Tick**（关键机制）；能源站 **+1/+2/+3**；能源点 **+4**。实测 500 局：能量收支比 1.04，主城 Lv5 在 541s 达成，死锁率 0%。
- **数值验证工具**：`test/selftest.js`（68 项规则自检）+ `test/simulate.js`（理性玩家跑批，`node test/simulate.js 500`）。模拟器**直接加载 config.js + game.js**，不重写公式。
- **用户明确不碰数值**：数值合理性全部由 AI 分析并给出调整方案，用户只做设计决策（规则层面的）。
- **建筑卡合成**：两张同类卡拖到相邻空格 → 直接建成 Lv2，**只收建造成本（免升 Lv2 物料）** —— 修正 V3.1 原作里"合成与先建后升成本完全相同、多花的卡零收益"的漏洞。
- **结算**：**建筑数量完全不计分**。`A 主城战果×1 + B 战略建筑×3 + C 资源点×3 + D 战场成果(÷5)×1`。
- 屏幕：横屏桌面 1280×720。沙盘 Canvas，UI DOM。数值全部集中 `config.js` + 实时调参面板。
- **资源点产出**：矿点/粮点 **+20**、能源点 **+4**。
- **时间**：单局 900s；经济 Tick 10s（8 步结算顺序 + `pendingUntilNextTick` 标记）；战斗为事件驱动。
- **AI**：P0 回防/收复 → P1 补兵 → P2 建设 → P3 **开牌与买卡** → P4 抢点 → P5 攻外围建筑（≥25 兵）→ P6 攻主城（≥45 兵）→ P7 待机。
