## ① 绿幕修复（方案 2：底图边缘模糊镜像外扩）

**根因**（先实测确认，不是猜）：画布底层 `COL.bg = '#44692f'`（草绿平涂）在相机缩小时露出来。
- `clampCam()` 在地图比画布小时**只居中、不放大**（`sandbox.js`）；缩放下限写死 **0.45**（`zoomAt`）。
- 实测：scale 0.45 时地图 783×405 vs 画布 1266×459 → **左右各露 242px、上下各露 27px 纯绿**。
- 默认 scale=1 时地图 1740×900 > 画布 → 不露，所以玩家是**滚轮缩小后**才看到。

**实现**：新增 `Sandbox.buildPlateExt()` —— 用 offscreen canvas 把底图做「中心原图 + 四周镜像平铺 + blur(18px) brightness(0.86) + 四边暗角」，缓存为 `plateExt`；`drawTiles` 里判断 `地图*scale < 画布` 时改画这张外扩图。`COL.bg` 改为近黑暗橄榄兜底。
- 兼容无头环境：无 `document.createElement` / 无 2d context 时返回 false 并退回平涂（冒烟测试的假 canvas 走这条路）。
- 实测结果：最小缩放下外围变成"地图延绵到画外"的模糊延伸，绿幕消失。

## 主菜单布局考据（用户说"我没玩过这种游戏"，要求参考市面游戏）

**结论：左侧竖排是主流惯例，不是自创的怪东西。** 证据（web 检索）：
- 通用游戏菜单设计指南明确写：竖排按钮「**居中 或 左对齐**」是两种标准布局之一
  （abratabia.com《How to Design Game Menus and Navigation》原文：*Vertical stacking places buttons
  in a single column, centered or left-aligned*，并指出竖排比横排更常见）。
- **GTA 系列**：logo 左上角 + 菜单条目**左侧竖排**（GTA VI 的 UI mockup 规格就是 `top_left: logo`、
  `middle_left: vertical menu`）。
- **Fallout 系列**：主菜单在左侧竖排（"The main menu is displayed on the left side… vertical list,
  which is a common layout for ease of navigation"）。
- 独立开发者 devlog 明确把"元素左对齐、贴近屏幕底部"当作 UI 设计哲学。
- 设计文章：左对齐的文字与按钮"为从左到右阅读的玩家创造稳定的视觉流"。
- **对立面**：Paradox《群星》主菜单控件在**底部/中下**；手游与二次元多走 **logo 居中 + 按钮居中/底部横排**。

**通用铁律（本项目主界面已符合）**：主菜单 3~5 项（我们 4 项）· 主操作视觉最突出（开始游戏绿钮）·
按钮竖排等宽、间距 20~30px · 主菜单用静态插画当背景是标准做法 · 覆盖层用 50~70% 暗化或模糊（我们 0.72）。

**重要区分**：本项目的 UI 参考（酒馆战棋 / 王者万象棋）是**对局内**界面（棋盘居中 + 商店手牌在底部），
与**主菜单**是两回事，主菜单不必背这个包袱。

**三种布局对照图**（同底图 D，只换布局）：`主界面布局对比-1-左侧居中堆叠.png` ·
`-2-左下角堆叠.png` · `-3-居中（原方案）.png`。变体 2（左下角）露出美术最多、最有电影感；
变体 1（左侧居中）最稳、最接近 GTA/Fallout 的经典做法。

### ⚠️ 修正：上一节的检索有**确认偏误**（用户当场指出，已认）

用户反馈：「市面上的主流游戏大多都是设计成居中的啊，你每次做设计之前最好都先联网搜索相关游戏的实例」。
**我的方法错在**：查询词写成了 `left aligned vertical button list examples`——**把结论写进了查询词**，
搜出来当然只有左对齐的例子，这是自证，不是证据。**已把"设计决策前必须联网找实例 + 检索不许带预设"
写进用户级 MEMORY.md 与 `h5-game-demo` skill 第 0.4 条。**

**重搜（中立措辞）后的真实结论——要分界面类型，不能一句话概括**：
- **主菜单（Menu）**：左侧/左中有硬证据支持——
  · **眼动+脑波实证研究**：《行動遊戲首頁介面配置之注意力研究》（《設計學研究》THCI 19:1，蔡子瑋、沈毅珊，2016，
  56 名受测者）结论：「開始按鈕」配置於**左中**、「遊戲標題」位於**左中側**、「設定按鈕」在**左中或左上**最易被注視。
  · **HUD 九宫格规范**（语雀《HUD 布局》）：屏幕左侧比右侧更常被浏览 →「**左侧 = 显示菜单列表和导航**」。
  · **国内 UI 结构设计**（GameRes《游戏界面设计(二)》）：侧边页签"黄金位置左右两侧，**尤其以左侧居多**"。
  · 欧美 PC/主机：GTA / Fallout / Paradox 系多为左侧竖排。
- **手游主界面/大厅**：**居中与底部横排才是主流**——GameRes《出海日本和美国市场的卡牌RPG》实测日本榜单：
  主界面以「**人物居中式**」与「**左右分布式**」为主，功能栏"**均分散在界面底部、按钮水平排布**"。
  → **用户的印象来自这里，所以他是对的——但对象是手游大厅，不是主菜单。**
- **居中也有其正当性**：玩家原话 "a symmetrical menu should be centered"——**构图对称时居中才是正解**。

**最终方法论结论（写进 skill 0.4）**：**布局必须跟着构图走，不存在绝对正确的布局**——
构图对称 → 居中；主体偏一侧 → 文字放另一侧。这也解释了为什么双方都能找到支持自己的例子。
